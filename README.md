# Мини-апп

Интерфейс на чистом HTML/CSS/JS, без сборки и зависимостей — как и прототип,
из которого он вырос. Дизайн-система сохранена целиком.

## Как это устроено

**Один адрес на всё.** `webapp_api.py` раздаёт и файлы интерфейса, и данные:
страница и API оказываются на одном источнике, поэтому CORS не нужен вовсе, а
адрес в `config.js` относительный и не требует правки никогда.

Наружу это выставляет быстрый туннель Cloudflare — у ноутбука нет внешнего
адреса, а Telegram открывает мини-аппы только по https.

**Адрес находится сам.** Быстрый туннель переименовывается при каждом запуске и
печатает новое имя только в свой лог. Бот читает `logs/tunnel.log` и переставляет
кнопку, когда адрес сменился, — раз в две минуты. Вписывать адрес руками значило
бы сломать кнопку в тот день, когда об этом забудут: после перезагрузки туннель
поднимется под другим именем, а в `.env` останется старое.

Обе части в автозапуске:

| Задача планировщика | Что делает |
|---|---|
| `CryptoSentimentBot` | бот вместе с API мини-аппа (порт 877) |
| `CryptoSentimentTunnel` | `cloudflared` — туннель на этот порт |

## Постоянный адрес

У быстрого туннеля один недостаток: имя меняется, и открытое приложение после
перезапуска придётся открыть заново. Лечится своим доменом в Cloudflare
(именованный туннель) или выкладыванием `webapp/` на GitHub Pages — тогда в
`config.js` вписывается полный адрес туннеля, а в `.env` постоянный адрес
страницы:

```
WEBAPP_URL=https://<логин>.github.io/<репозиторий>/
```

Заполненный `WEBAPP_URL` перебивает автопоиск — на то он и постоянный.

## Проверка без Telegram

```bash
python -c "import webapp_api, log_setup; from dotenv import load_dotenv; load_dotenv(); webapp_api.start(877); input()"
```

Открыть `http://localhost:877`.

Профиль и свежие коллы покажут заглушку: личность подтверждается подписью
Telegram, а её выдаёт только сам мессенджер. Так и должно быть — на этом
держится платный доступ.

## Экраны

| Экран | Что показывает | Откуда данные |
|---|---|---|
| Рынок | темп коллов, точность по классам, простой, свежие сигналы | `/api/market` |
| Монеты | вселенная сканера с ценами и недельным графиком | `/api/coins` |
| Разбор | вердикт, согласие, **вход/цели/стоп**, восемь компонентов, новости | `/api/coin/<id>` |
| Коллы | сигналы и их исходы; без подписки — только отработавшие | `/api/signals` |
| Профиль | подписка и какие классы коллов приходят | `/api/me` |

## Безопасность

Сервер смотрит в открытый интернет, поэтому:

* **личность — только из подписи Telegram.** Иначе любой подставил бы чужой
  `chat_id` и получил подписку даром. Сверка через `hmac.compare_digest`:
  обычное сравнение строк выходит на первом несовпавшем символе, и по времени
  ответа подпись подбирается побайтово;
* **статика не выходит за `webapp/`.** Без проверки пути запрос вида
  `/../../.env` отдал бы токен бота всему интернету — а токеном можно вернуть
  звёзды плательщикам и рассылать что угодно подписчикам.

## Чего здесь нет и почему

В макете были потоки крупных кошельков («+214 млн $»), разбивка объёма по биржам
и золотые кресты EMA. Таких источников у бота нет, и рисовать правдоподобные
цифры в приложении, по которому человек принимает решения о деньгах, нельзя.
Панели убраны, а не заполнены заглушками: пустая рамка с надписью «скоро»
занимает пол-экрана и обещает то, чего никто не обещал.

Что появилось вместо них — **вход, цели и стоп**. Их бот теперь считает
по-настоящему, от суточного диапазона монеты (`targets.py`). Это закрывает
давнюю дыру: раньше колл говорил «лонг» и молчал о том, когда выходить.

Стейблкоины и обёртки в списке не показываются — тем же отсевом, что и у
сканера. Предлагать разобрать монету, которую бот принципиально не анализирует,
непоследовательно.
